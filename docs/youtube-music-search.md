# YouTube and YouTube Music: finding the real album, not a pirate copy

Status: **problem list and research, written as the starting point of a separate fix session** (new branch, new Claude session). Nothing more is fixed in branch `feature/0014-resolve-time-catalog-enrichment` than what section 14 lists. Written 2026-10-01. What the fix session decides becomes an ADR.

Terms used: **Topic channel** = a channel YouTube makes by itself for an artist, named "Artist - Topic". **OLAK playlist** = the official YouTube Music album playlist, with an id that starts with `OLAK5uy_`. **InnerTube** = the internal API that the YouTube Music website and app use. **ToS** = terms of service.

## 1. The problem

The YouTube apps find the real album of a real artist at once. hodnota finds pirates. Two real cases from 2026-10-01:

| Case | What hodnota showed | What is right |
|---|---|---|
| Search `nostromo ecce lex` (Album) | 7 of 10 rows were YouTube rows, and none is the album. See the list below. | `music.youtube.com/playlist?list=OLAK5uy_kuX1PX8vApNMXS8Unv4yK7K7fpipFjEbc` |
| Open the share page of *Ecce Lex* by Nostromo | YouTube link `PLUHFk0JDea8OCs0FhiMyei4Lm-5j-S_px`: a pirate upload by the user `somuchdeath18` | the same OLAK playlist |
| Search `metalica load` (Album) | only fan uploads such as "Metallica · Load (Full Album)" | two official playlists: `OLAK5uy_nf8K8yHuLThX0qvPGCIM2eBKndPale4vU` ("Album - Load") and `OLAK5uy_nn9_UEJTyKvU65JlglPBRMp9eWyxOTFWc` ("Album - Load (Remastered Deluxe Box Set)") |

The YouTube rows of the first search, in order: "Nostromo - Ecce Lex (Full Album)" (`somuchdeath18`, a pirate); "Mix - Nostromo" (an automatic mix, not an album); "Nostromo" by two private users; "NOSTROMO (Geneva, CH)" (a different thing); "Nostromo Discography" (a user's playlist); "Albums" (a playlist in the band's own channel, not an album).

## 2. What the code does today, and why it fails

| # | Stage | What happens | Why it is wrong |
|---|---|---|---|
| RC1 | Search (`YouTubeStreamingProvider.SearchAsync`) | One `search.list` call with the user's typed words, type `playlist` or `video`, 50 results. | `search.list` searches **all uploads** by text relevance. Anyone can write "Artist - Album (Full Album)", so pirates rank high. The official OLAK playlists are not in the results at all (section 4). |
| RC2 | Relevance filter (`SearchResultRelevanceFilter`) | A result stays if **one** query word of 3+ letters appears in its title or channel. | The word "nostromo" alone keeps every playlist with that word. This is why 7 of 10 rows were noise. |
| RC3 | Merge (`SearchResultMerger`, `SearchResultKey`) | A YouTube row joins a catalog row only if the normalized artist and title are equal. | The "artist" of a YouTube result is the **uploader's channel**, so it never equals the real artist. The good row never gets a YouTube link, and junk rows stay as separate rows. |
| RC4 | Resolve, first version (`SearchResultNameMatcher`) | Accepted a playlist whose **title** contained the artist and the album title. | A title proves nothing. The pirate's title was perfect. **Fixed in Phase 0** (section 10). |
| RC5 | No model of "real" | Nothing in the code tells an official release from an upload. | Without it, any rule is a guess (section 6). |
| RC6 | Quota | The search page spends one `search.list` call per search, and resolve can spend one more per new item. | Since June 2026 `search.list` has its own bucket of **100 calls per day** per project (section 4). About 50 user actions use it up. |
| RC7 | "Album" | The code looks for a playlist. | On YouTube an album is only a playlist. The API has no album object. The official one cannot be found by search. |
| RC8 | A name is not an identity | The Phase 0 rule compares the **channel title** with the artist name. | The probe found **6** different channels titled "Nostromo - Topic" (and one "NOSTROMO - Topic"), **4** titled "Metallica - Topic", and two plain "Metallica" channels. These are different artists with the same name, or duplicates. A channel title alone cannot say which artist it is, so the rule can accept a Topic video of another band that has the same name, if the album title is equal too. A channel id from a trusted source, or a check of the content (section 6), is needed. |

## 3. How YouTube organizes music

| Thing | What it is | Who owns it | Can we tell it is official? |
|---|---|---|---|
| Topic channel | "Artist - Topic", made by YouTube from distributor deliveries ("auto-generated by YouTube") | YouTube | **Yes**: the channel title ends in " - Topic". Users can create a channel with that name, but it is hard to do by accident. |
| Auto-generated track video | A video whose description has these paragraphs in order: "Provided to YouTube by *distributor*", "*Track* · *Artist*", the **album name**, "℗ *label*", "Released on: *date*", credits (lyricist, composer, producer), "Auto-generated by YouTube." (**verified** on *Rude Awakening* and *Ain't My Bitch*). Category 10, `licensedContent` true. **No ISRC** in the description. | the Topic channel | Yes, with the channel check. The description alone can be copied. |
| OLAK playlist | Official album playlist, title "Album - *Title*" | the channel **"YouTube"** (verified by our probe) | Yes: id prefix `OLAK5uy_` and owner "YouTube". The tracks inside belong to the Topic channel. |
| Official Artist Channel | The artist's own channel, merged with the Topic channel by YouTube | the artist | Not through the API (no "verified" field was found). |
| Partner channels | Labels and distributors | the label | Partly (`licensedContent`, see below). |
| User uploads and playlists | Anything else, including pirate "Full Album" copies and "Mix" playlists | any user | No. This is where `search.list` leads. |

## 4. What the YouTube Data API v3 can do for music

Sources are in section 13. "Verified" means our own probe on 2026-10-01.

**Facts**

- `search.list` takes `type` = video, channel or playlist. Useful options: `videoCategoryId=10` (Music, only with `type=video`), `channelId` (search inside one channel), and `q` with `-` for NOT and `|` for OR.
- Not useful or gone: `relatedToVideoId` was removed in August 2023. `topicId` stopped working as before in February 2017. Do not rely on either.
- There is **no** field or endpoint for YouTube Music albums or `MPREb_` browse ids.
- `playlists.list?id=OLAK5uy_…` works and returns channel "YouTube" and title "Album - …" (**verified**).
- `search.list type=playlist q="Metallica Load"` returned 50 results and **zero** OLAK playlists (**verified**). There is no documented condition under which search returns them.
- Fields that help to judge a video: `snippet.channelTitle` (ends in " - Topic"), `snippet.description` ("Provided to YouTube by …"), `playlistItems.snippet.videoOwnerChannelTitle` and `videoOwnerChannelId` (who uploaded each track of a playlist), `contentDetails.licensedContent`, `snippet.categoryId`.
- `licensedContent=true` means "a rights holder claimed it". Claimed fan uploads have it too, so it is **not** proof of "official".

**Quota (since 2026-06-01)**

| Method | Cost |
|---|---|
| `search.list` | own bucket, **100 calls per day** |
| `playlists.list`, `playlistItems.list`, `videos.list`, `channels.list` | 1 unit each, from a shared bucket of 10,000 units per day |

Design rule: spend `search.list` only when nothing cheaper can answer. Verification with `videos.list` (up to 50 ids per call), `playlists.list` and `playlistItems.list` is almost free. Whether Google raises the search bucket on request is **unverified**.

**Answered by the live experiments (section 9)**

1. `search.list type=channel q="Nostromo - Topic"` **does** return Topic channels, but several with the same title (RC8). It cannot say which one is the right artist.
2. `playlists.list?channelId=<Topic channel>` does **not** list albums. For *Metallica - Topic* it returned 3 playlists and no OLAK playlist. For *Nostromo - Topic* it returned nothing.
3. A playlist search restricted to the Topic channel (`channelId`) returned nothing, as expected: OLAK playlists belong to the channel "YouTube", not to the Topic channel.
4. `search.list type=video videoCategoryId=10 q="Nostromo Ecce Lex"` **does** return Topic videos (2 of 15 results: *Ecce Lex* and *Rude Awakening*, both on the album), mixed with pirate uploads and the band's own videos. For `q="Metallica Load"` only 2 of 15 were Topic videos, and both were bonus tracks of the box set. The description of a Topic video **does** name the album.
5. The YouTube videos that Discogs lists are **not** reliable (section 7).

Still untested: a **video** search restricted to the Topic channel with the album title as `q` (the description holds the album name, so the search may match it). See E9 in section 9.

## 5. How YouTube Music itself finds the album, and the ToS

The YouTube Music website and app call InnerTube. The open-source library `ytmusicapi` shows how: a `search` request with the filter "albums" returns `browseId` (`MPREb_…`) and `audioPlaylistId` (the OLAK id). YouTube ranks its **own catalog** there, which is why the apps never show pirates. This is the only route we found that returns the exact album playlist.

It is also against the rules:

- **YouTube API Developer Policies III.D.7:** "You must not use undocumented APIs without express permission … You must not reverse engineer undocumented YouTube API services."
- **III.E.6:** an API client must not "scrape YouTube Applications". Because hodnota already holds a Data API key, this rule applies to the **same project**. The risk is losing the key and the quota, not only the InnerTube access.
- **YouTube Terms of Service:** no access by "automated means (such as robots, botnets or scrapers)" without written permission.

Plain risk statement: for a private hobby project the likely penalty is a banned key, not a lawsuit. Any ToS risk also makes a later public launch harder. Research recommendation: never ship InnerTube to real users. This is decision D3 (section 11). It is the owner's to make.

Other tools: Odesli/song.link closed its public API on 2026-07-31. MusicBrainz Harmony has no YouTube Music provider. How Songwhip and Soundiiz match is not public.

## 6. What "real" means: authenticity signals

| Signal | Strength | Note |
|---|---|---|
| Playlist id starts with `OLAK5uy_` and its channel is "YouTube" | strong (album) | not discoverable by search |
| `playlistItems` owner channel title ends in " - Topic" | strong | checks the tracks of a playlist, 1 unit |
| Video channel title ends in " - Topic" and the description starts "Provided to YouTube by" | strong (track) | the album name is in the description |
| The description names the album, the label (℗) and the release date, and they equal what the catalog providers say | strong when combined with a Topic channel | checks that it is the right artist among same-name channels (RC8). Catalog release dates are not mapped yet. |
| The channel is the artist's own channel (name equals the artist) | medium | a pirate can name a channel after the band; same-name channels exist (RC8) |
| `licensedContent=true` | weak | also true for claimed fan uploads |
| The title contains the artist and album | **none** | anyone can write it. This was the bug in RC4. |

Rule: nothing is shown as a match unless it has at least one strong signal, or the artist's-own-channel signal plus an exact title. "No link is better than a pirate link."

## 7. Free sources of YouTube ids (no YouTube search call)

| Source | What it can give | Measured on 2026-10-01 |
|---|---|---|
| **Wikidata** property P4300 (YouTube playlist ID, accepts OLAK ids) and P2397 (channel id), joined by the MusicBrainz release-group id (P436) | the OLAK id of an album | Only about 3.5% of albums with a MusicBrainz id have an OLAK id (8,488 of 244,901). *Load* and *Nostromo* have none. |
| **MusicBrainz** URL relations | streaming links of a release | *Ecce Lex*: nothing for YouTube. *Load* (40 releases): Spotify, Deezer, Tidal, Qobuz, Apple, **no** YouTube. Limit: 1 request per second, a real User-Agent is required. |
| **Discogs** `videos` array of a master or release | YouTube video ids that people attached | *Ecce Lex*: 10 usable videos, **all fan uploads** (9 by `PursuitofX`, 1 by `Torulv`), `licensedContent` false for all 10, **0** Topic. *Load*: 16 videos: 14 on the official `Metallica` channel (lyric and music videos, not the album), 1 Topic video, 1 fan upload. Checked with one `videos.list` call per album (1 unit, no search call). |

Result: none of these sources gives the OLAK **album** link for our two examples. Discogs videos are useless for a small band (fan uploads only) and give only singles and lyric videos for a famous one, so they are a weak leg of any strategy.

## 8. Strategies compared

| # | Strategy | Finds the real album? | Rejects pirates? | Cost per item | ToS risk | Size in .NET |
|---|---|---|---|---|---|---|
| S1 | Official API only. Songs: search videos in the Music category, accept only Topic videos. Albums: find a Topic track whose description names the album. | Songs: probably yes. Albums: a **track** link, not the album playlist. | Yes (Topic check) | 1 search + 1 `videos.list` | low | small, 150–250 lines |
| S2 | S1 plus free sources first: Wikidata OLAK id, then S1 (the Discogs-videos leg proved weak, section 7) | Famous albums: yes, if the id exists (about 3–5%, none for our two examples). Others: a track link. | Yes | 0–1 search, cheap calls | low | medium, 300–500 lines (2 clients, 1 req/s throttle, cache) |
| S3 | Topic channel path: find "Artist - Topic", then search inside it | A Topic channel does **not** list albums (E4) and there are several channels with the same title (RC8). Searching videos inside it is untested (E9). | Yes | 1–2 searches | low | medium |
| S4 | InnerTube (`ytmusicapi`-style) | **Yes**, the exact OLAK and `MPREb_` links, best hit rate | Yes (YouTube ranks its own catalog) | no quota; breaks when YouTube changes | **high** | large; the parsing needs upkeep |
| S5 | Odesli API | — | — | — | — | not available |

Recommendation (a proposal for the fix session): **S1 as the base for songs and for a verified track of an album, S2's Wikidata step for famous albums, S4 only if the owner accepts the risk in D3.** For an album with no OLAK id, the official API can only give a verified Topic track, not the album playlist. If the product must show the exact album playlist for small bands, there is no ToS-clean route we know of. The real fix also needs a way to pick the right artist among same-name channels (RC8).

## 11. Open decisions for the fix session

| # | Question | Recommendation |
|---|---|---|
| **D1** | Remove YouTube from the **search list** and use it only at resolve time? It saves quota and removes the junk rows. The catalog providers already find the item. | Yes. ADR 0008 made YouTube the first search source; this would change that. |

Free sources (no YouTube quota). MusicBrainz needs a real `User-Agent` header and at most 1 request per second:

```
# MusicBrainz: release by barcode, then the links of its release group
GET https://musicbrainz.org/ws/2/release?query=barcode:UPC&fmt=json
GET https://musicbrainz.org/ws/2/release-group/RG_MBID?inc=url-rels&fmt=json

# Wikidata (SPARQL at https://query.wikidata.org/sparql): the OLAK playlist of an album,
# joined by the MusicBrainz release-group id
SELECT ?playlist WHERE {
  ?album wdt:P436 "RG_MBID" ;
         wdt:P4300 ?playlist .
  FILTER(STRSTARTS(?playlist, "OLAK5uy_"))
}

# Discogs: YouTube videos that people attached to the album (no login needed for this read)
GET https://api.discogs.com/masters/36338        -> videos[].uri
```
