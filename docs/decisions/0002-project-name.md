# 0002. Project name

Status: accepted

## Context

`docs/roadmap.md` called for a naming brainstorm as the project's first open item. In practice, the brainstorm already happened before this repo existed: the repo had to be created (and named) on GitHub before any of the current docs could be written into it, so a name was picked at that point rather than left blank.

## Decision

Keep **hodnota** as the project's working/draft/pilot name.

`hodnota` comes from Ukrainian slang "годнота" — roughly "something worthy of attention." It was chosen because domain names for it are widely available and the word is rarely used elsewhere on the web, so it's unlikely to collide with an existing product or brand.

An alternative, **lanka**, was also considered: Ukrainian "ланка" — a link in a chain, a natural symbol for a web link, which fits a links-aggregation service well. It was rejected for two reasons: the name is already heavily used by other, unrelated services and products, and non-Ukrainian speakers are likely to read it as a reference to Sri Lanka rather than the intended meaning.

This is explicitly a working name, not a final brand commitment — the project keeps the option to rebrand later, once it has more identity or traction, without that being treated as reopening this decision.

## Consequences

- `README.md` gets a short note explaining the name and its working/draft status, linking here for the full reasoning.
- `docs/roadmap.md`'s "come up with a name" item is checked off — the decision made is "keep the working name, revisit later," not "pick a permanent brand," but it resolves the open roadmap item either way.
- A future rebrand is anticipated, not a failure of this decision — no new ADR is needed just to acknowledge that possibility; one would be needed if/when a rebrand actually happens.
